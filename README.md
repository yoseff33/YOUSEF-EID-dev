# نظام مؤسسة يوسف عيد المطيري لقطع غيار السيارات

نظام ويب ثابت يُرفع على **GitHub Pages**، ويستخدم **Supabase** للمصادقة وقاعدة البيانات والمزامنة بين الأجهزة.

## بيانات المنشأة المثبتة

- الاسم: مؤسسة يوسف عيد المطيري لقطع غيار السيارات
- السجل التجاري: 7054534024
- الموقع: C2MH+P5، الصناعية، حفر الباطن 39925
- لا يوجد في المبيعات أو الفاتورة أي حقل لاسم المشتري أو العميل.

## المميزات الموجودة

- تسجيل دخول وصلاحيات: مدير، موظف مبيعات، مشرف مخزون.
- ربط البيع والشراء والإرجاع والجرد بالموظف المنفذ.
- أصناف، صور قطع، رقم قطعة، باركود، سعر شراء وبيع، وحد نقص.
- موردون: الاسم، الهاتف، الحساب البنكي/الآيبان، والملاحظات.
- فواتير شراء ترفع المخزون تلقائيًا.
- فواتير بيع تخصم المخزون تلقائيًا.
- إرجاع كلي أو جزئي يعيد الكمية للمخزون مع سبب الإرجاع.
- جرد فعلي مع تقرير فروقات الهالك أو الفقدان أو الزيادة.
- اقتراح طلبات شراء حسب حد النقص ومبيعات آخر 30 يومًا.
- تقارير الأرباح، تكلفة البضاعة، هامش الربح، ضريبة القيمة المضافة، ودوران المخزون.
- رسوم بيانية للمبيعات.
- سجل تدقيق للعمليات.
- عمل محلي عند انقطاع الإنترنت باستخدام IndexedDB وطابور مزامنة بمعرّف فريد لكل عملية.
- PWA قابلة للتثبيت من المتصفح.
- طباعة فاتورة وحفظ PDF بدون اسم مشتري.

## مهم قبل التشغيل

GitHub Pages لا يشغّل قواعد بيانات أو تسجيل دخول بنفسه. لذلك:

- GitHub Pages: يستضيف ملفات الواجهة فقط.
- Supabase: تسجيل الدخول، قاعدة PostgreSQL، الصور، RLS، ودوال العمليات.
- مفتاح `anon` مسموح وضعه في الواجهة، لكن **ممنوع نهائيًا** وضع `service_role` داخل ملفات GitHub Pages.

## 1) إنشاء مشروع Supabase

1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح **SQL Editor**.
3. انسخ محتوى `supabase/schema.sql` وشغّله كاملًا.
4. من **Authentication > Users** أنشئ أول مستخدم يدويًا.
5. نفّذ في SQL Editor، مع استبدال البريد:

```sql
update public.profiles
set role = 'admin', full_name = 'يوسف عيد المطيري', is_active = true
where email = 'YOUR_EMAIL@example.com';
```

## 2) إعداد الواجهة

افتح `assets/js/config.js` وعدّل:

```js
supabaseUrl: "https://YOUR_PROJECT.supabase.co",
supabaseAnonKey: "YOUR_ANON_KEY",
```

تجد القيم في **Project Settings > API**.

لإضافة الرقم الضريبي لاحقًا ضعه داخل:

```js
vatNumber: "رقمك الضريبي المكون من 15 رقمًا",
```

## 3) تفعيل إدارة المستخدمين من داخل الموقع

صفحة المستخدمين تستدعي Supabase Edge Function حتى لا ينكشف مفتاح الإدارة.

ثبت Supabase CLI ثم من جذر المشروع:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy manage-users --no-verify-jwt
```

الدالة تتحقق بنفسها من رمز المستخدم ومن أن دوره `admin`. متغيرات `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` تكون متاحة تلقائيًا داخل مشروع Supabase المستضاف.

إذا لم تنشر الدالة، بقية النظام يعمل، لكن إنشاء الموظفين يتم يدويًا من لوحة Supabase.

## 4) رفع الموقع على GitHub Pages

1. أنشئ مستودعًا جديدًا.
2. ارفع **محتويات المجلد** إلى جذر المستودع، وليس المجلد نفسه.
3. افتح **Settings > Pages**.
4. اختر **Deploy from a branch**.
5. اختر `main` والمجلد `/ (root)`.
6. من Supabase افتح **Authentication > URL Configuration** وأضف رابط GitHub Pages في:
   - Site URL
   - Redirect URLs

## الصلاحيات

### المدير
- جميع الصفحات والبيانات.
- التقارير المالية والضريبية.
- إدارة المستخدمين والصلاحيات.
- سجل العمليات.

### موظف المبيعات
- إنشاء فواتير البيع.
- عرض المخزون.
- إرجاع الفواتير.
- لا يستطيع تعديل الأصناف أو رؤية التقارير المالية أو المستخدمين.

### مشرف المخزون
- إدارة الأصناف والصور والباركود.
- إدارة الموردين والمشتريات.
- الجرد وتعديل الكمية من خلال الجرد فقط.
- لا يستطيع البيع أو رؤية تقارير الأرباح.

## المزامنة وعدم الاتصال

نسخة الويب تستخدم **IndexedDB** بدل SQLite لأن المتصفح على GitHub Pages لا يملك SQLite أصليًا. المبدأ نفسه مطبق:

1. القراءة من النسخة المحلية عند انقطاع الإنترنت.
2. عمليات البيع والشراء والإرجاع والجرد تُحفظ في طابور محلي.
3. عند عودة الإنترنت تُرسل إلى دوال Supabase.
4. `client_request_id` يمنع تكرار العملية لو أعيد الإرسال.
5. لو حدث تعارض حقيقي، مثل بيع كمية لم تعد متوفرة في السحابة، تبقى العملية بحالة فشل للمراجعة ولا يتم تعديل المخزون خطأً.

> PowerSync مناسب لاحقًا عند بناء تطبيق Flutter أو React Native بقاعدة SQLite حقيقية. نسخة GitHub Pages الحالية لا تحتاجه لتعمل، ولا يمكنها استخدام SQLite الأصلي مثل تطبيقات الجوال وسطح المكتب.

## ملاحظات أمان

- سياسات RLS موجودة في `schema.sql`.
- خصم وزيادة المخزون تتم داخل دوال PostgreSQL ذرية وليست داخل JavaScript فقط.
- لا تعدّل الكميات مباشرة من جدول `products`؛ استخدم شراء أو بيع أو إرجاع أو جرد.
- لا تضع `SUPABASE_SERVICE_ROLE_KEY` داخل `config.js` أو GitHub.

## الملفات الرئيسية

- `index.html`: هيكل الواجهة.
- `assets/css/style.css`: التصميم المتجاوب والطباعة.
- `assets/js/app.js`: الصفحات والتفاعل.
- `assets/js/api.js`: الاتصال بـ Supabase والمزامنة.
- `assets/js/local-db.js`: التخزين المحلي وطابور العمليات.
- `supabase/schema.sql`: الجداول، RLS، التقارير، ودوال المخزون.
- `supabase/functions/manage-users/index.ts`: إدارة المستخدمين بأمان.
- `service-worker.js`: PWA وحفظ ملفات الواجهة.
